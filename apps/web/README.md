# EventHub web app

The attendee experience: sign in, browse a tenant's events, reserve tickets with a hold that
counts down on the server's clock, pay, and see what you bought.

It was generated by [Lovable](https://lovable.dev) from
[`docs/frontend/lovable-prompt-01.md`](../../docs/frontend/lovable-prompt-01.md), synced to its
own repository (`Alfred-Goh02/eventhub-ticketing`), and brought in here, where it is
typechecked, linted, tested and built in CI. **This directory is the source of truth.** The
Lovable repository is a design sandbox; changes made there are brought across by hand, not
synced.

## Running it

The compose stack must be up (see the root README), with the gateway on port 8000.

```sh
pnpm install --ignore-workspace
pnpm run dev
```

Then open **http://acme.eventhub.localhost:5173** (or any other tenant's subdomain, e.g.
`globex`). The tenant is the first label of the host, and the API is the same host on
port 8000, which is what the gateway's CORS rule allows. `*.localhost` resolves to this machine
in every major browser, so no hosts-file entry is needed. The seeded test accounts are in
`services/auth/prisma/seed.ts`.

The dev server listens on 127.0.0.1 only, like every other port in this repository. Opened on
any other host (Lovable's preview, for instance) the app uses the sample data in
`src/api/mock.ts` instead of the API.

## Checks

```sh
pnpm run typecheck   # tsc, with the strict settings in tsconfig.json
pnpm run lint        # eslint + prettier
pnpm run test        # vitest
pnpm run build       # TanStack Start, via Lovable's Vite config, for a Node server
```

It is not a member of the root pnpm workspace: it imports nothing from the services, and
as a member it would be copied into the backend image. It installs from its own
`pnpm-lock.yaml`.

## Its image

`docker build apps/web` builds the image the EKS cluster runs (`infra/web`): nitro's
`node-server` output and nothing else, served by `node .output/server/index.mjs` on port
3000, as the `node` user. The build targets Node because `vite.config.ts` says so; the shared
Lovable config would otherwise build for Cloudflare. `infra/eks/up.mjs` builds it, tags it
with the commit, and pushes it to its own ECR repository.

The page calls the API at the same host on port 8000, so in production the web app is
served on 443 and the gateway on 8000, under the same tenant host; the gateway's CORS rule
allows exactly that origin.

## Stack

TanStack Start (React 19, TanStack Router and Query), Vite, Tailwind 4 and shadcn/ui. That
is Lovable's template; the prompt asked for React Router, and Lovable used its own default.
Every route that touches the API renders in the browser only (`ssr: false`), so the server
never renders a tenant's data.
